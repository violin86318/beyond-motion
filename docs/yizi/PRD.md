## 1. 产品定位与目标

一字美学是一组以汉字结构组织画面、将字义转化为意象的持续视觉作品，作为个人网站的作品子站展示。访客能完整浏览合格作品、按日期查看细节与短文；创作者能追溯每次选字、生成、审阅、替换与发布。

目标用户：个人网站访客、对汉字视觉创作感兴趣的读者；维护者为 violin 与原 Remio 自动任务。

核心使用场景：从主站「图像」或「全部小站」进入；手机上翻看作品；查看某一字的完整画面和解读；维护者处理缺图、低质稿及每日新作。个人品牌首页保持现有定位，不混排整套历史作品。

目标：完整清点历史来源，找回可用版本；以明确标准审核作品，低质作品进入修复队列；稳定恢复「字中有画」的核心方法；维持永久去重、单次提交与已授权预算；每一条公开记录都有可追溯的合格母图和正确文字。

成功判据：

- 清点覆盖率：已发现来源100%有指纹、版本与处置理由；此指标独立于图片是否合格。
- 历史日期覆盖率：审计区间每日期有「候选／待找回／无记录／停用／已审」等真实结论，不能把找不到图自动当成生成失败。
- 公开入选：100%通过技术检查与实际视觉审阅，明确拒绝项0次复活；没有证据的历史图不得冒充 approved。
- 文案与署名：缺失、历史未记录、现代创作及经核实引文各自准确标注，无编造亲历或作者。
- 每日运行：同日最多一次真实提交，旧字不再被选为新一期；失败与未知结果不触发重画。
- 当前完成标准：先通过本机预览验收；公开发布与首次定时端到端另验，不由文档提交代替。

## 6. 需求详述与验收

### YZ-01 历史完整性

- 触发／现状：用户检查到内容不全；此前只用选中图库的数量证明完整，漏掉被淘汰日期与文案缺失。
- 输入：原图目录、旧登记、原运行历史、实际版本引用；来自现有资料，不扩大第三方上传。
- 输出：逐文件来源表、逐日期处置表、缺图与缺文案队列，各有证据与下一步。
- 判断／验收：Given 148个已发现文件，When 对账，Then 每文件有唯一指纹及理由；Given 125日期，Then 每日期有真实状态，6个无图日期不得标成功或失败而无依据。
- 边界：审计区间内的自然日不等于承诺作品数；发现新来源后增量对账，不覆盖旧结论。
- 异常：来源读不到或矛盾时保持 unresolved；原文缺失不能凭空补写历史。
- 优先级／来源：P0，2026-10-17「目前内容不全」。

### YZ-02 版本、排除与同字作品

- 触发／现状：淘汰横竖版及用户拒绝的「润」曾被误展示。
- 输入：日期、字、来源指纹、重做引用、明确否定记录。
- 输出：每件作品的版本链、入选版本指针与拒绝原因。
- 判断／验收：Given 同日多版和发送副本，When 导入，Then 只使用已核对版本；Given 被否定指纹或版本，Then 普通导入与新作归档均不能恢复它。
- 边界：同字不同日期的历史作品不能因新生成去重而被删；同日并非天然只有一个文件。
- 异常：最新版不一定最好；没有最终选择证据的版本待审，不按最高v号自动批准。
- 优先级／来源：P0，用户明确要求撤下淘汰与不合格作品。
- 修复提案：现有按日期拒绝「润」会同时阻止未来合格重制版，应升级为具体版本／指纹拒绝与新版本独立审核；在升级前不绕过日期拒绝。

### YZ-03 品质审核

- 触发／现状：用户指出低质图仍在画廊；61件候选尚无本轮逐件审阅证据。
- 输入：实际母图、主题简报、历史反馈、参考锚点和技术检查。
- 输出：reviewer、时间、作品指纹、通过／拒绝／待审、逐项理由与问题位置；历史与新作使用同一核心标准。
- 判断／验收：Given 只能核尺寸或OCR，Then 不得填审美通过；Given 图片实际可看，When 审阅，Then 必须判断字是否正确、字画是否融合、意象是否合题、层次细节是否成立、有无乱码和错误署名。
- 边界：没有逐件看图不能给61件统一批准；网页外壳轻盈不要求作品本身浅色极简。
- 异常：无法加载或无法视觉审阅时留待审，不能重画代替审阅，也不扣回预算占位。
- 优先级／来源：P0，「质量偏低，不符合要求，需要审核更新」。
- 审阅量表与锚点选择为Agent提案，见第7节；没有自动打分生效。

### YZ-04 缺失与低质作品更新

- 触发／现状：58日期仅剩淘汰来源、6日期无图、部分现有候选品质存疑。
- 输入：问题队列、能找回的母图、旧版本、经明确授权的修复预算。
- 输出：找回结果或带新版本号的替代候选；旧版保留，入选指针在审阅通过后更新。
- 判断／验收：Given 有更好原版本，Then 先找回与审阅；Given 需要新生成，Then 必须有该修复范围的费用授权，且生成后重新审阅；Given 修复失败，Then 不覆盖旧数据、不自动重试。
- 边界：每日新一期授权不包含批量补历史；不把旧图裁成方形、加边、放大就算重制完成。
- 异常：无法确认历史字时先核字；不能为了填满日期随意另选字。
- 优先级／来源：P0，用户要求完整内容与审核更新。
- Agent提案：修复使用关联原作品的独立repair任务，不释放永久用字，不伪装今天的新一期；费用单独预占与记录。尚未实现，禁止绕过去重直接提交。

### YZ-05 提示词版本

- 触发／现状：多用途目标、固定浅纸配色、可入画文字槽位与主题结构不足可能造成风格漂移。
- 输入：原完整方法、实际历史反馈、主题brief、明确模型与规格。
- 输出：固定版本模板、最终实际发送文本、版本号与哈希；本轮交付 [v2候选](prompt-template-v2.candidate.txt) 和 [评估说明](prompt-evaluation.md)。
- 判断／验收：Given 同一模板与brief，When 编译，Then 只有主题字段变化，无未填变量与自动英文降级；Given 未出图验证的v2，Then 不自动替换正在运行的版本。
- 边界：提示词不能保证汉字正确或代替实际质检；通道和实际型号由执行器核对。
- 异常：变量遗漏或语义冲突在提交前停止；接口失败不删节或换模型重画。
- 优先级／来源：P0，「提示词怎么样优化一下」。

### YZ-06 主题简报

- 触发／现状：每日需要不同字义与意象，不能固定翠绿与山水。
- 输入：永久字表返回的可用字，人工或任务撰写的字义、构图关系、配色、现代短文。
- 输出：冻结brief和编译prompt；字与运行、图片、文案绑定。
- 判断／验收：Given 一个确定字，Then 模型不得重新选字；概念应说明意象如何组织到部件／笔画／负形；题材可变化而核心结构保持。
- 边界：不要求每字相同风景；不把无参考的“高级、专业”形容词当验收条件。
- 异常：无法形成清楚映射的主题重新准备brief，准备不产生费用与占位；已提交后不得换字重跑。
- 优先级／来源：P1，既有 #47 字中有画恢复方向；细化字段为Agent提案。

### YZ-07 永久去重

- 触发／现状：历史出现重复字，旧14日窗口与漏读归档已修复。
- 输入：永久字表、旧登记、已知失败／换字、样本与待审用字。
- 输出：规范化用字记录、原子日期锁、run标识。
- 判断／验收：Given 已用字或其规范等价形式，When 作为新一期选字，Then 拒绝；并发只能保留一次；失败／待审／未知状态继续占位。
- 边界：不靠图库文件是否存在推断能否生成；历史重制使用专门授权设计，不能删除字表来执行。
- 异常：历史损坏或缺口影响选字时停止；不自动清空或重置词库。
- 优先级／来源：P0，用户多轮明确要求去重并补齐验证。

### YZ-08 预算与生成安全

- 触发／现状：用户明确每日预算，曾出现结果未知与多次生成问题。
- 输入：有效费用授权、全局通道、实际型号、当期报价、日期与月度账本。
- 输出：至多一次提交，真实请求结果与账单／保守占用记录。
- 判断／验收：每日最多1张/1元，每自然月最多30元；按每次1元保守预占，31天月份额度耗尽时跳过；报价不明或超限在提交前停止。
- 边界：目前指定VMG单一路由、Tuzi实际API型号gpt-image-2.5-1k、1K方形；该字符串为供应商路由名，不能声称已验证官方上游；不承诺所有1K结果恰为1024像素。

## 7. 视觉审核与提示词验证方案（Agent提案，待确认效果）

### 7.1 两类检查分别记录

技术必过：真实解码；1:1；新作原生结果达到1K档（记录实际像素）；版本/字/日期关联；资源不损坏；无已拒绝指纹。历史图片即使有2048尺寸，也不能据此断言其原生分辨率或没有被放大。

视觉必过：主题字结构正确；画面意象参与构成字形；意象与字义有联系；主体分量与留白合适；细节与色彩层次成立；无模糊缺笔、乱码、错误署名。任一硬缺陷均不能靠总分抵消。

如需评分，建议字画融合、主题表达、构图、细节、系列协调5项各0—4分，单项至少3且总分至少16；此为拟议辅助标准，不能自动代填，也不能覆盖用户明确拒绝。

### 7.2 参考与反例

优先复核历史05-27「让」、05-30「澄」、06-02「悟」的真实母图与原任务记录，作为候选参考；这些名称来自历史记录，不把旧助手说的“用户认可”直接升级为本次已批准锚图。

明确反例：05-31某些被替换的浅底极简版本，以及06-05「润」的普通字与独立山水分离。拒绝记录针对具体版本；不能据此把所有浅色作品或所有山水意象一概否定。

### 7.3 候选模板验证

先完成变量编译与文本合同检查；再在明确授权的单张测试范围内，以同一brief保存实际发送文本、模型、像素和结果，按上面标准审阅。无需为了A/B比较额外生成旧版。第一张通过后再决定是否扩展到不同结构/字义测试；历史已用字若重制必须进入专门修复流程。

本轮v2未调用模型、未生成验证图、未替换原Remio现用v1。当前是可审阅候选，不能宣称优化效果已验证。

## 8. 数据、状态与接口约定

维护侧最少字段：work_id、date、character、source_fingerprint、version_id、supersedes、technical_review、visual_review、reviewer、review_evidence、prompt_version/hash、brief、provider/model（历史可unknown）、request_ref、budget_reservation、delivery_state、publication_state。

公开侧最少字段：作品字、日期、批准后的派生图、可公开解读、真实署名、已核来源与必要AI说明。不输出私人文件路径、原运行消息、密钥或账单响应。

```text
历史来源 → 已对账 → 候选 → 实际审阅 → approved / rejected / needs_review
缺失来源 → unresolved → 找回候选 / 已核未运行 / 待授权修复
每日新作 → prepared → reserved → submitted → needs_review
                               └→ submitted_unknown（保持占位，找回同次结果）
approved → 本机更新 → 发布验收 → published（当前尚未接通公开步骤）
```

版本与审阅应绑定图片指纹，避免换图后沿用旧批准；此为待实现数据强化。重复导出幂等；更换入选版本先写新记录再切指针；不能删除费用/字表来重试。
